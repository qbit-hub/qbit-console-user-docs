# مانیتورینگ منابع

Qbit Console آخرین snapshot پذیرفته‌شده و تاریخچه snapshotهای نگهداری‌شده را نمایش می‌دهد. مشاهده snapshot و history **passive** است: بازکردن صفحه یا تغییر بازه زمانی polling جدید یا فرمانی روی سرور ایجاد نمی‌کند. در کنار این رفتار passive، تب **مانیتورینگ** یک action صریح برای **دریافت متریک تازه** نیز دارد که فقط با capability `monitor` اجرا می‌شود.

## آخرین وضعیت منابع

در صفحه جزئیات سرور ممکن است این داده‌ها نمایش داده شوند:

- مصرف CPU؛
- مصرف حافظه؛
- مصرف دیسک؛
- network received / transmitted؛
- uptime؛
- load average یک، پنج و پانزده دقیقه‌ای؛
- زمان مشاهده و زمان پذیرش snapshot توسط Qbit؛
- source و schema version داده.

اگر snapshot قدیمی باشد، پنل آن را با وضعیت **Stale / قدیمی** مشخص می‌کند. داده stale همچنان آخرین observation پذیرفته‌شده است و نباید با وضعیت لحظه‌ای سرور اشتباه گرفته شود. `Unavailable` بودن connection نیز مفهوم جداگانه‌ای دارد و به وضعیت اتصال سرور/Agent اشاره می‌کند.

## تاریخچه منابع

از صفحه سرور گزینه **تاریخچه منابع** را باز کنید. بازه‌های فعلی شامل:

- آخرین ساعت؛
- آخرین ۲۴ ساعت؛
- همه snapshotهای نگهداری‌شده.

صفحه تاریخچه trendهای CPU، حافظه و دیسک را از همان داده‌ای که API برگردانده رسم می‌کند. تغییر بازه زمانی polling جدیدی ایجاد نمی‌کند.

## دریافت متریک تازه

در تب **مانیتورینگ** صفحه جزئیات سرور، **دریافت متریک تازه** یک action جدا از مشاهده snapshot/history است. اگر Agent سرور capability `monitor` را اعلام کرده باشد، Qbit یک typed remote operation برای جمع‌آوری تازه متریک‌ها ایجاد می‌کند. وضعیت این درخواست به‌عنوان operation قابل پیگیری است.

اگر capability `monitor` وجود نداشته باشد، Console به‌جای اجرای fallback یا shell خام، قابلیت را unsupported نشان می‌دهد.

## تفسیر زمان‌ها

Qbit زمان‌های domain را به‌صورت ISO-8601 نگه می‌دارد. در رابط کاربری می‌توانید تقویم Gregorian یا Jalali را انتخاب کنید؛ این انتخاب فقط نحوه نمایش و ورود تاریخ را تغییر می‌دهد و مقدار canonical backend را تغییر نمی‌دهد.

## وقتی داده‌ای وجود ندارد

اگر snapshot در دسترس نیست:

1. وضعیت connection و enrollment سرور را بررسی کنید؛
2. مطمئن شوید Agent و منبع ingest مورد انتظار فعال‌اند؛
3. در صورت stale بودن داده، زمان آخرین observed/accepted را بررسی کنید؛
4. اگر به داده تازه نیاز دارید و `monitor` پشتیبانی می‌شود، از action **دریافت متریک تازه** استفاده کنید؛
5. خطای شبکه یا API را از پیام صفحه جدا از وضعیت خود سرور در نظر بگیرید.

:::info
Refresh مرورگر به معنی اجرای command روی ماشین ریموت نیست. فقط action صریح **دریافت متریک تازه** یک typed operation برای جمع‌آوری تازه ایجاد می‌کند.
:::
