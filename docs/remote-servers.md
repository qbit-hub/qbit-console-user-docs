# سرورهای ریموت

سرور ریموت در Qbit یک **رکورد مدیریتی برای یک ماشین شخص ثالث** است. Qbit مالکیت سرور را تغییر نمی‌دهد و ایجاد این رکورد معادل خرید سرور یا ساخت VM نیست.

## افزودن سرور

از Workspace موردنظر وارد **Infrastructure → Servers** شوید و **افزودن سرور ریموت** را انتخاب کنید.

فرم فعلی این فیلدها را دریافت می‌کند:

- **نام نمایشی**: نامی برای تشخیص سریع سرور در پنل؛
- **نوع اتصال**: `SSH` یا `Agent`؛
- **آدرس یا شناسه سرور**: hostname، IP یا remote reference دیگری که سرور را مشخص کند؛
- **شناسه اعتبارنامه**: اختیاری و فقط به‌صورت reference غیرشفاف؛
- **Tags** و **Labels**: اختیاری، هر مورد در یک خط با قالب `key=value`.

:::danger[اطلاعات محرمانه را وارد نکنید]
فیلد credential reference برای **رمز عبور، token، private key یا secret خام** نیست. فقط شناسه مرجعی را وارد کنید که سیستم عملیاتی شما برای credential تعریف کرده است.
:::

## وضعیت اتصال و enrollment

در فهرست سرورها، وضعیت connection و enrollment نمایش داده می‌شود. مقادیر رایج عبارت‌اند از `Pending`، `Available`، `Unavailable` و `Disabled` برای اتصال، و `Pending`، `Active`، `Failed` و `Disabled` برای enrollment.

## جزئیات سرور

صفحه جزئیات شامل metadata ثبت‌شده و آخرین resource snapshot پذیرفته‌شده است. این صفحه می‌تواند CPU، حافظه، دیسک، network counters، uptime و load average را نمایش دهد.

بازکردن صفحه جزئیات **هیچ polling جدید یا فرمان مستقیمی روی سرور اجرا نمی‌کند**.

در نسخه فعلی، همین صفحه تب‌های **نمای کلی**، **مانیتورینگ**، **کانتینرها**، **عملیات**، **ترمینال** و **هشدار و ارسال‌ها** را نیز دارد. actionهای زنده فقط وقتی فعال می‌شوند که Agent سرور capability لازم را اعلام کند. بازکردن تب‌ها به‌تنهایی command ایجاد نمی‌کند؛ actionهایی مانند **دریافت متریک تازه**، lifecycle کانتینر یا اتصال ترمینال صریح هستند.

## ویرایش metadata

در قرارداد فعلی می‌توانید tags و labels را ویرایش کنید. نام نمایشی در قرارداد فعلی metadata update immutable است.

## غیرفعال‌کردن سرور

گزینه **غیرفعال‌کردن سرور** فقط lifecycle رکورد Qbit را تغییر می‌دهد. این عملیات به معنی shutdown، reboot یا حذف ماشین نزد ارائه‌دهنده سرور نیست.
